## 자율협업 마커 · 팀 공통 규칙 (CLAUDE.md 준수)

**세션 종료 순서 (필수 3단계)**
1. 파일 저장 완료 확인 (실제 저장됨 확인)
2. `[[기록: 완료 | 구체적 내용]]` 또는 `[[기록: 진행중 | ...]]` 기입
3. `[[자율종결]]` 마커 배치

**단계별 처리**
- **완료** → 파일 저장 → `[[기록: 완료|...]]` → `[[자율종결]]`
- **이견 있음** → 반론을 파일에 기술 → 파일 저장 → `[[기록: 완료|반론 포함]]` → `[[자율종결]]`
- **판단 불가** → `[[결재: 담당팀 | 제목]]` → 대표 결재 대기 (자율종결 안 함)

**금지 사항**
- ❌ "대표님 확인 필요합니다"로 판단 미루기 → ✅ `[[결재:...]]` 사용
- ❌ 파일 저장 전 `[[자율종결]]` 배치 → ✅ 저장 완료 후
- ❌ `[[기록:...]]` 없이 `[[자율종결]]` 단독 → ✅ 항상 기록 먼저
- ❌ 내용 없이 `[[기록: 완료|...]]` → ✅ 구체적 내용

## 팀 1 · 고객센터팀 (제이크 수집 → 폴 1차 필터링) · 아이디어 수집

```
[[자율 지시: 아이디어샘물-수집]]

**실행 요일:** 화·목 (주 2회)
오늘이 화·목이 아니면 세션 종료.

**세션 시작 시 준비**
오늘 날짜(YYYY-MM-DD) 폴더가 없으면 생성한다.

**1단계 · 아이디어 수집 (사원 제이크) → 1차 필터링 (팀장 폴)**

절차 원칙 (2026-07-20 학습 유지)
- 제이크: 수집 초안 저장 후 세션 넘김. 폴 명의로 필터링 판정 부착 금지.
- 폴: 제이크 산출물을 받아 1차 필터링 결과를 동일 파일 하단에 append.

제이크 수집 원칙
- 사용자 불편·니치·반복 요청 위주 12~15건
- 소스: 온라인 커뮤니티(클리앙·디시·나무위키), 앱스토어 리뷰, 블로그·커뮤니티 질문
- 한국 특화·앱화 가능한 것 우선

수집 리스트 구조 (건당)
1. 아이템 이름
2. 원문 요약 (2~3문장)
3. 출처 (URL 2~3개)
4. 공감도/반복빈도 (매우 높음/높음/중간/낮음)
5. 비고 (경쟁 앱·특이사항)

제이크 관찰 (파일 하단)
- 통과 가능성 순위 (스타 등급 또는 코멘트)
- 폴 필터링 참고 사항

폴 1차 필터링 (동일 파일에 append)
- 15건 중 마케팅팀 승계 가치 있는 것 선별
- 판단 축: 한국 특화·앱화 가능성·경쟁 여지·구조적 벽
- 통과 코멘트 + 마케팅팀 승계 유의사항 명시

저장: `프로젝트/아이디어샘물/[오늘날짜]/00-수집리스트.md`

세션 종료 순서
1. 파일 저장 완료 확인
2. [[기록: 완료 | 제이크 N건 수집·폴 M건 승계]]
3. [[자율종결]]

이견/판단 불가 시
- 이견: 반론을 파일에 기술 → 저장 → [[기록: 완료|반론 포함]] → [[자율종결]]
- 판단 불가: [[결재: 고객센터팀 | 제목]] → 대표 결재 대기
```

```

`{날짜}/00-수집리스트.md` 확인. 없거나 폴 필터링 미완이면 "통과 없음"으로 종료.

**2단계 · 시장필터 (대리 벤 초안 → 팀장 제니 판정)**

절차 원칙 (2026-07-20 학습 유지)
- 벤은 초안까지 저장 후 세션 넘김. 팀장 명의 판정·최종 확정 문구 부착 금지.
- 제니는 벤 초안 검증 후 최종 확정 세션에서 판정 append.

스코어링 축 (6축 · 5점 만점 · 총 30점)
1. 필요도 — 절박도
2. 타깃 명확성 — "누구 누구"라고 한 줄에 그려지는가
3. 지속성 — 반복 빈도
4. 차별화 여지 — 기존 서비스 대비 우리만의 각도
5. 지불 의지 — 실제 돈 낼 성향
6. 1인 감당 가능성 — 심사·컴플라이언스·엔터프라이즈 부담

뻔함 등급: A(새 카테고리) / B(익숙+새 각도) / C(흔함+뻔한 각도) / D(대기업 카피)

컷라인
- 총점 20 미만 → 컷
- 뻔함 D → 컷
- 뻔함 C → 25점↑만 통과
- 대기업 5어절 유사 → 자동 컷
- 20↑이어도 지불 의지 3↓ / MVP 6주+ 중 하나면 컷

팀장 제니 판정
- 벤 초안 근거 재검증 (링크 실측·대기업 카테고리 확인·스코어 조정)
- 통과 확정·컷 확정·개발팀 승계 유의사항
- 억지로 채우지 않는 원칙 유지 (4번째 슬롯 강제 승격 없음)

저장: `프로젝트/아이디어샘물/[오늘날짜]/01-시장필터결과.md`

세션 종료 순서
1. 파일 저장 완료 확인
2. [[기록: 완료 | 통과 N건·컷 M건. 파일: {날짜}/01-시장필터결과.md]]
3. [[자율종결]]

이견/판단 불가
- 이견: 반론을 파일에 기술 → 저장 → [[기록: 완료|반론 포함]] → [[자율종결]]

## 팀 5 · 기획전략실 (사마의) · HTML 보고서 및 배포

```
[[자율 지시: 아이디어샘물-보고서및배포]]

**실행 요일:** 화·목 (주 2회)
오늘이 화·목이 아니면 세션 종료.

**세션 시작 시 준비**
오늘 날짜(YYYY-MM-DD) 폴더를 확인한다.

**1단계 · HTML 보고서 제작**

읽어야 할 파일 (없으면 그 단계는 "통과 없음")
- 프로젝트/아이디어샘물/[오늘날짜]/00-수집리스트.md
- 프로젝트/아이디어샘물/[오늘날짜]/01-시장필터결과.md
- 프로젝트/아이디어샘물/[오늘날짜]/02-프로토타입.md
- 프로젝트/아이디어샘물/[오늘날짜]/03-디자인컨셉.md

보고서 구조
1. 오늘의 요약 — 수집 N → 1차 M → 2차 K → 프로토 J → 디자인 J (한눈에)
2. 오늘의 하이라이트 — 가장 밀 만한 항목 1개를 상세 소개 (이유 포함)
3. 아이템별 상세 — 각 최종 후보마다 접힘 형식으로:
   원본 불편 → 시장 판단 → 프로토타입 → 디자인 컨셉을 한 흐름으로
4. 오늘의 이슈 — 어느 단계에서 걸렸는지, 왜 통과 없음이었는지
5. 대표 판단 요청 — 각 후보 옆에 "출시 진행 / 보류 / 폐기" 자리 제공
   (대표가 이 보고서 하나로 최종 결정)

HTML 원칙
- 모바일 우선 (대표가 바깥에서 볼 수 있게)
- 시각적 위계 명확
- 상세는 접힘 처리로 스크롤 부담 축소
